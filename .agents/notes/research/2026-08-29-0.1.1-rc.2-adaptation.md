# Agent Note: 0.1.1-rc.2 适配验证(peerDependencies 滞后是唯一实质障碍)

> Status: verified — 含端到端真机验证(远程连接 + 远程工作区 + 七工具路由/读写文件均正常, 2026-08-29)
> 范围: 本仓库 packages/dsh-ssh 在 DSH 0.1.1-rc.2 + pnpm 11.24 + node 24 上的安装与运行时验证。

## Problem

前次会话(结论见聊天记录)判定 dsh-ssh/dsh-ssh 在 0.1.1-rc.2 上"装都装不上",根因列为三条: ①pnpm 构建门禁; ②9 个 peer 全部 missing(声明 ^0.1.0-rc.6); ③`@deepseek-ai/dsh-client-ui-primitives` 在 0.1.1 中"根本不存在"。并据此推断 seam API(defineTool / agent/created / ctx.tools.register / bindTypertRemote / settingsNamespace / FsError / parseExitStatus)大概率已漂移、需重写 client.js。

## Decision

实际逐项核验后发现,**seam API 并未漂移**,唯一实质障碍是 package.json 的 peerDependencies 版本范围 + pnpm 构建门禁。适配仅改 3 个文件、0 行源码:

1. `packages/dsh-ssh/package.json`
   - peerDependencies: 8 个 `^0.1.0-rc.6` → `^0.1.1-rc.2`(cordis ^4.0.1 与 schemastery ^3.18.1 不变); 移除 `@deepseek-ai/dsh-client-ui-primitives`(它不再是 npm 包, 而是 web 前端内的静态模块别名)。
   - `dsh.client.inject`: 由 `["@deepseek-ai/dsh-client-ui-primitives"]` 改为当前客户端插件包名(api-remotes / client-connection / client-locale / client-runtime / client-ui-conversation / client-ui-settings / client-ui-tool / client-ui-workspace)。
2. `pnpm-workspace.yaml`: `allowBuilds: {cpu-features:false, ssh2:false}` 跳过 ssh2 的可选原生加速器 cpu-features 的 node-gyp 构建(纯 JS 加密回退, 同时免除原生工具链硬要求)。
3. `pnpm-lock.yaml`: 由 `pnpm install` 重生成, 全部解析到 0.1.1-rc.2(0 处 rc.6)。

## Alternatives

- 曾尝试 `onlyBuiltDependencies: []` + `ignoredBuiltDependencies` → pnpm 11.21 不认 `ignoredBuiltDependencies`(dist 中 0 处匹配), 仍 `ERR_PNPM_IGNORED_BUILDS`。
- 曾尝试 `neverBuiltDependencies` → 未验证(改回 `allowBuilds:false` 后一次通过)。
- 锁定 DSH 到 0.1.0-rc.x → 不采纳, 与"跟随 0.1.1"目标相反。

## Consequences(已验证事实)

- 宿主侧全部具名导出在 0.1.1-rc.2 仍存在且签名一致: `defineTool`/`ToolDefinition`(dsh-tools)、`FsError(message, code)`(dsh-fs)、`settingsNamespace`(dsh-settings)、`bindTypertRemote(service,key,opts?)`/`remoteMethods`(dsh-typert-protocol)、`parseExitStatus`(dsh-shell)、`ESCALATION_TARGETS`/`approveEscalation(request,approval)`/`validateEscalationArgs`/`escalationHintMarker`/`sandboxDenialMarker`(dsh-sandbox)。
- tools/*.js 早已使用**新** `defineTool` 契约(parameters 为 value-schema DSL、必填 `output.{schema,render}`、presentCall/presentResult/isConcurrencySafe/timeoutMs), 与 0.1.1-rc.2 完全一致, 无需改。
- settings 服务 `register(ns,schema,{base,applies})`、`describe()` 的 `{ns,revision}`、`mutate(ns,ops,revision)` 的 `{op:'set'|'unset',path,value}` 契约未变。
- 客户端 `window.__ModuleLoader__.load({id,factory})` 形态与 `require("@deepseek-ai/dsh-client-ui-primitives")` **仍然有效**(0.1.1-rc.2 自身插件如 dsh-client-ui-agent-preset 仍这样用); client.js 的 slots 注册(`settings.section` / `tool.call.toolview` / 两个 `directoryFlow`)与当前 Slot 树逐项对应。
- `scripts/client-selfcheck.mjs` 通过; `scripts/verify-agent-created.mjs`(DSH_SSH_VERIFY_SKIP_SSH=1)在真实组合中通过: 远端 cwd 遮蔽全部 7 工具、本地 cwd 零影响——证明 `apply` + `agent/created` 钩子在 0.1.1-rc.2 上真实运行。

## 出处

- peer 包版本: DSH core 安装目录(见根 AGENTS.md §7「本地 DSH checkout」)下 `node_modules/@deepseek-ai/`(dsh-tools/dsh-fs/dsh-settings/dsh-typert-protocol/dsh-sandbox/dsh-shell 均 0.1.1-rc.2)。
- 新 defineTool 契约: dsh-tools/lib/types/schema.d.ts L239; FsError: dsh-fs/lib/types/types.d.ts L169; settings 选项: dsh-settings/lib/types/index.d.ts L24; 客户端模块系统: dsh-client-modules/lib/index.js。

## 注册表安装验证(addendum, 同 2026-08-29)

`pnpm pack` 打 tarball → `dsh plugin --profile <p> add <tarball>` 走与 npm 注册表完全相同的路径(真实依赖解析 + profile 侧构建门禁), 全链路通过:

1. **首次 add 必失败于 profile 侧构建门禁**: `ERR_PNPM_IGNORED_BUILDS: cpu-features@0.0.10, ssh2@1.17.0`。`initProfile` 生成的 profile `pnpm-workspace.yaml` 已预置 `allowBuilds: {cpu-features: "set this to true or false", ssh2: "set this to true or false"}` 占位。改成 `false` 后再 add 即成功(纯 JS 加密回退, 无需原生工具链)。
2. **reconcile 正常**: 成功后 `@dsh-ssh/dsh-ssh` 进入 `dsh.profile.bundles`, `node_modules/@dsh-ssh/dsh-ssh/` 落盘, `ssh2/diff` 及传递依赖装入 profile。
3. **peer 回退解析正确**: profile `node_modules` 顶层无 `@deepseek-ai/*`, 运行时经 `healProfilesModuleFallback` 从 DSH 安装目录解析(0.1.1-rc.2)。实测 boot + `agent/created` 遮蔽全部 7 工具。
4. **`ROUTED_TOOL_MARKER` 是 `Symbol('@dsh-ssh/dsh-ssh/routed-tool')` 而非 `Symbol.for(...)`**: 插件内部自洽, 但 `scripts/verify-agent-created.mjs` 用 `import('../tools.js')` 取的是脚本所在(monorepo)副本的 Symbol, 与"单独安装副本"运行中的 Symbol 不相等, 故跨副本验证时影子数会误报为 `[]`。dev/link 流(脚本与插件同副本)不受影响; 要验证已安装副本须从 `node_modules/@dsh-ssh/dsh-ssh/tools.js` 取 marker。属测试脚本可移植性限制, 非插件缺陷。

## 出处

- 注册表路径验证: 本机 `pnpm pack` tarball + `dsh plugin add` + 临时脚本(用安装副本的 marker)实测 `VERIFY-OK registry: all 7 tools shadowed`。
