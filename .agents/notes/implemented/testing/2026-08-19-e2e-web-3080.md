# Agent Note: 3080 全工具 Web E2E(scripts/e2e-web-3080.mjs)
Status: implemented

## Problem
- 需要一个可复跑、断言的端到端验证:通过真实 web-app 的 HTTP API 驱动一个远端占位工作区会话,跑全工具用例,确认路由实际生效。

## Decision
- **单文件、可复跑、断言失败即 exit(1)**:`scripts/e2e-web-3080.mjs`,驱动 http://127.0.0.1:3080(dsh-ssh-dev profile;`E2E_BASE` 可覆盖)。
- 信封:`POST /api/<method>` 体 `{type:"client-request",rpcId,method,params:{},payload}`;会话:session.create{cwd,agentPreset:"standard"} → session.selectModel(显式 fusion-router/deepseek-v4-flash,否则默认模型不确定)→ session.prompt → session.history 轮询新增事件出现 turn/end。
- 工具事件解析:tool/call 与 tool/result 按 callId 配对;单回合判定用 ingested 游标只取增量(否则历史累积事件重复统计)。
- **8 用例**(cwd=远端占位):bash 前台(hostname+cat note 内容)、write、read 读回、edit 改回、glob、grep、后台链(bash run_in_background:true → job_list running → job_output 含 TICK → job_kill 成功,jobId 从「started background job <id>」正则提取)、清理(rm 文件保留目录)。每用例独立开 session(隔离后台任务状态与模型行为)。
- 输出纪律:只打印汇总表(≤60 行),轮询不打原始 JSON。

## Alternatives considered
- **复用官方测试框架 / mock**：官方 `dsh-e2e` 多为 Web 驱动 + 模型 mock 或轻量 stub，难以验证真实 `agent/created` 钩子遮蔽与 SSH 远端链路；mock 会掩盖跨进程/跨机器真实故障，排故成本高，故选用真机直连。
- **单文件直连 HTTP 信封**：直接以 `POST /api/<method>` 的 `client-request` 信封驱动真实 web-app（`session.create/selectModel/prompt/history`），无额外测试框架依赖，单文件可复跑、断言失败即 `exit(1)`，便于 CI 与本地手工复现；轮询仅取增量事件，避免历史累积误判。
- **8 用例独立 session**：后台任务（`run_in_background` + `job_list/job_output/job_kill`）与模型行为在会话内有状态，若共用单会话会互相污染（前一用例的 job 状态、轮询游标、模型上下文）；独立 session 隔离状态，保证每用例可独立重试与定位，且 `jobId` 从文案正则提取不跨会话串扰。

## Consequences
- 二轮实跑 8/8 全绿（`fail=0`，退出码 `0`）。
- 后台任务时序坑：原 5×5s=25s 在模型生成 + 轮询延迟下 `job_list` 时已 `completed`；改 12×5s=60s 保证 `job_list` 时仍 `running`。
- `edit` 断言须 case-insensitive（结果文案是小写 `updated`）。
